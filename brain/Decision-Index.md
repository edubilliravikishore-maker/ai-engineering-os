- [ADR-004: Rule Engine Foundation & Checkpoint 3 Scope](../adr/ADR-004.md) — **Accepted — 2026-08-25.** Records the Rule & Policy Engine architecture and the scope of Checkpoint 3. Supersedes nothing.
  - [4.1 Generic Rule Engine](../adr/ADR-004.md#41-generic-rule-engine-with-explicit-strongly-typed-python-rules) — a reusable engine with explicit strongly typed Python rules; no DSL, no expression language, no LLM evaluation.
  - [4.2 Hybrid Evaluation](../adr/ADR-004.md#42-hybrid-evaluation) — independent failures aggregate; only rules with a declared, failed prerequisite are skipped.
  - [4.3 Deterministic Ordering](../adr/ADR-004.md#43-deterministic-os-owned-rule-ordering) — a fixed OS-owned stage order; agents and runtime configuration never reorder rules.
  - [4.7 Condition Vocabulary Moves To Domain](../adr/ADR-004.md#47-the-condition-vocabulary-moves-to-the-domain-layer) — `domain` owns the vocabulary; `state` declares, `rules` evaluates; `rules` must not depend on `state`.
  - [4.8 Full Phase 0 Revisit](../adr/ADR-004.md#48-checkpoint-2-revisit-performed-in-full-at-checkpoint-3-start) — QA defect scope fields, required Task plan linkage, and the `ORIGINATING_PLAN_ACTIVE` declaration; that rule itself stays deferred.
  - [4.9 Evidence Standards Fail Closed](../adr/ADR-004.md#49-evidence-standards--undefined-capabilities-fail-closed) — no standard is invented for FRONTEND or QA; an undefined standard fails closed, never as "no evidence required". `DB_VERIFICATION` is not mandatory.
  - [4.10 Six Representative CP3 Rules](../adr/ADR-004.md#410-checkpoint-3-rule-scope--six-representative-rules) — the engine is proven against six real rules before the rule library is expanded.
  - [4.11 Four-Way Condition Classification](../adr/ADR-004.md#411-rule-expansion-boundary--four-way-condition-classification) — implemented, PENDING_RULE_EXPANSION, SATISFIED_BY_DOMAIN_INVARIANT, and BLOCKED_CONDITIONS partition the vocabulary.
  - [4.12 Checkpoint 6 Safety Gate](../adr/ADR-004.md#412-checkpoint-6-safety-gate) — the Kernel may not operate while a required Foundation v1 condition is unenforced.
  - [4.13 Required Conditions Derived From The Vertical Slice](../adr/ADR-004.md#413-foundation-v1-required-conditions-derived-from-the-vertical-slice) — the required set is derived from the approved vertical slice, never authored as a separate checklist.
  - **Amendment — Checkpoint 3 Audit Rulings, 2026-08-29.** Three Builder rulings following the Checkpoint 3 implementation audit; §4.1 to §4.13 stand unchanged.
    - [4.14 Different Feature Is Out Of Scope](../adr/ADR-004.md#414-different-feature-is-out-of-scope--adr-003-311-contradiction-resolved) — resolves the ADR-003 3.11 contradiction; a defect resolving to a different Feature does not block the Feature being accepted.
    - [4.15 QA History Is Audit History](../adr/ADR-004.md#415-qa-history-is-audit-history--the-authoritative-qa-result-mechanism-remains-open) — selecting the authoritative QA result belongs to the future Kernel/context loader; the Rule Engine evaluates the supplied facts and takes no view on their cardinality. The authoritative/current QA-result mechanism **remains OPEN** and must be designed before Checkpoint 6.
    - [4.16 Dangling Feature References Are Out Of Checkpoint 3 Scope](../adr/ADR-004.md#416-dangling-feature-references-are-out-of-checkpoint-3-scope--the-seven-fact-context-is-unchanged) — the seven-fact RuleContext is unchanged; Checkpoint 3 does not claim to validate Feature-reference existence.

- [ADR-005: Persistence Architecture & Checkpoint 4 Scope](../adr/ADR-005.md) — **Accepted — 2026-09-02.** Records the persistence architecture and the scope of Checkpoint 4. Supersedes the Implementation Blueprint section 14 item 1 *recommendation* only; amends the section 7.1 classification of `work_packages` and the checkpoint ownership of the event and audit tables. No Design Session, ADR-001, ADR-002, ADR-003, or ADR-004 ruling is altered.
  - [5.1 A Single actors Table](../adr/ADR-005.md#51-a-single-actors-table) — one `actors` table with `role` as a column; **no `coordinators` table and no Domain Registry**, so ADR-003 3.10 is respected and D-2/D-3 stay deferred.
  - [5.2 Child Tables vs JSONB](../adr/ADR-005.md#52-child-tables-when-the-os-reasons-about-the-contents-jsonb-when-the-object-is-whole) — a child table when the OS reasons about the contents; JSONB when the object is treated as a whole. Not every nested object becomes a table.
  - [5.3 Database Is The Durable Source Of Truth](../adr/ADR-005.md#53-the-database-is-the-durable-source-of-truth) — domain objects are the behavioural representation loaded from persisted state; reconstruction **fails** rather than returning an invalid object or silently repairing one.
  - [5.4 Generic Base Plus Domain-Specific Repositories](../adr/ADR-005.md#54-generic-base-repository-plus-domain-specific-repositories) — reusable mechanics in the base, domain queries in their own repositories; **no generic CRUD surface**.
  - [5.5 Service Layer Owns The Transaction](../adr/ADR-005.md#55-the-serviceuse-case-layer-owns-the-transaction) — repositories use the supplied session and never commit; **the transaction owner is the Checkpoint 6 Kernel and is not built at Checkpoint 4**.
  - [5.6 Optimistic Locking](../adr/ADR-005.md#56-concurrency--optimistic-locking) — **supersedes the Blueprint section 14 item 1 recommendation of `SELECT FOR UPDATE`**; concurrent modification is detected and reported, never silently overwritten. No domain model is modified.
  - [5.7 No Generic Delete Capability](../adr/ADR-005.md#57-no-generic-delete-capability) — no `repository.delete()`, foreign keys `RESTRICT`, no cascade, no `ON UPDATE CASCADE`, and **no ABANDONED/CANCELLED/STOPPED state**. D-6 stays deferred.
  - [5.8 Immutable History And The Work Package Hybrid](../adr/ADR-005.md#58-immutable-history-and-the-work-package-hybrid) — **amends Blueprint section 7.1**: `work_packages` is a hybrid, not append-only. DRAFT editable, SUBMITTED durable, submitted content immutable, and the approved lifecycle transitions remain the sole authority for status. ADR-003 3.5 is unchanged.
  - [5.9 Application Identity, Database Persistence Metadata](../adr/ADR-005.md#59-application-generated-identity-database-generated-persistence-metadata) — application-generated UUIDs; **existing domain timestamps stay domain-owned**; database timestamps are separate persistence metadata, are **never mapped into domain objects**, and **must not be used for ordering, filtering, or authoritative QA-result selection**. Reinforces ADR-004 4.15.
  - [5.10 Migration Grouping And Immutability](../adr/ADR-005.md#510-migrations-grouped-by-coherent-schema-change-applied-migrations-immutable) — grouped by coherent schema change; an applied migration is never edited. `0001_baseline` is left untouched.
  - [5.11 Repositories Return Domain Objects Only](../adr/ADR-005.md#511-repositories-return-domain-objects-only) — ORM models never cross the repository boundary; the Rule Engine and higher layers never receive a SQLAlchemy model.
  - [5.12 Persistence Exceptions At The Repository Boundary](../adr/ADR-005.md#512-persistence-exceptions-are-translated-at-the-repository-boundary) — `NotFoundError`, `ConcurrencyConflictError`, `PersistenceError` in `storage`, **not** in `domain/errors.py`; the repository reports, the service decides.
  - [5.13 Events And Audit Deferred To Checkpoint 5](../adr/ADR-005.md#513-events-and-transition-audit-deferred-to-checkpoint-5) — **corrects Blueprint section 11 and section 15**: `os_events` and `state_transitions_audit` both belong to Checkpoint 5. Checkpoint 4 creates neither.
  - [5.14 Database Constraints And Indexes](../adr/ADR-005.md#514-database-constraints-and-indexes) — constraints for fundamental integrity, business rules stay in the domain; evidence-based indexes; no views. **Closes the persistence half of Blueprint section 14 item 19** via foreign keys on the defect scope columns, without changing ADR-004 4.16's ruling about the rule layer. Records the new `features.slug` uniqueness rule and the `VARCHAR` + `CHECK` status representation.
  - [5.15 Reaffirmed, Not Newly Decided](../adr/ADR-005.md#515-reaffirmed-not-newly-decided) — PostgreSQL/SQLAlchemy/Alembic already decided by ADR-002; no caching; SQLAlchemy's standard connection pool. **No new runtime dependency.**

- [ADR-006: Event Layer Architecture & Checkpoint 5 Scope](../adr/ADR-006.md) — **Accepted — 2026-09-04.** Records the event and notification architecture and the scope of Checkpoint 5. Supersedes the Implementation Blueprint section 7.2 step 7 *illustration* only; amends that section's transition-audit description and channel name. No Design Session, ADR-001, ADR-002, ADR-003, ADR-004, or ADR-005 ruling is altered.
  - [6.1 Total Ordering By Database Sequence](../adr/ADR-006.md#61-total-ordering-by-database-generated-sequence) — a `GENERATED ALWAYS AS IDENTITY` column is the sole authority on append order; **no timestamp orders events**, so ADR-005 5.9 and ADR-004 4.15 are reinforced rather than quietly broken.
  - [6.2 Notification Emitted Inside The Transaction](../adr/ADR-006.md#62-the-notification-is-emitted-inside-the-committing-transaction) — **supersedes the Blueprint section 7.2 step 7 post-commit emit**; `pg_notify()` runs inside the committing transaction, so a committed transition is never left unannounced. The Validation-First sequence itself is unchanged.
  - [6.3 Transition Audit Records Both Outcomes](../adr/ADR-006.md#63-the-transition-audit-records-both-outcomes) — **amends Blueprint section 7.2**: `state_transitions_audit` records every evaluated attempt with an `outcome` column, not refusals alone, so enforcement history lives in typed columns rather than in the deferred payload schema.
  - [6.4 Closed Thirteen-Entry Event Vocabulary](../adr/ADR-006.md#64-a-closed-thirteen-entry-event-vocabulary) — exactly the thirteen Blueprint section 6 event types, enforced by a `CHECK` generated from the enumeration. `EscalationRaised` is recorded; **D-1 stays deferred and no `BLOCKED` state is created**.
  - [6.5 Strict Envelope, Unconstrained Payload](../adr/ADR-006.md#65-strict-envelope-unconstrained-payload) — the envelope is strictly typed; **per-event-type payload schemas are deferred to Checkpoint 6 or later**, because an append-only row cannot be reshaped once a guess proves wrong.
  - [6.6 Subscribers Resume By Sequence](../adr/ADR-006.md#66-subscribers-resume-by-sequence-position-held-in-memory) — drain-then-listen on every reconnect, position held in memory. Makes ADR-002's "wake-up only" structurally true. **Recorded limitation:** no event is lost, but universal observation across a subscriber restart is **not** guaranteed.
  - [6.7 A Single Notification Channel](../adr/ADR-006.md#67-a-single-notification-channel) — one channel; subscribers filter. **Replaces the Blueprint section 7.2 `task_events` channel name.** The thin envelope of section 14 item 3 is unchanged.
  - [6.8 Initiator Attribution And The Null Actor ID](../adr/ADR-006.md#68-initiator-attribution-and-the-null-actor-id) — reuses the existing `Initiator = ActorRole | SystemActor`; actor id is nullable with a `CHECK` permitting null **only** for `OS`. **No sentinel id, no OS row in `actors`, and `ActorRole` is unchanged.**
  - [6.9 The Bus Receives A Session](../adr/ADR-006.md#69-the-bus-receives-a-session-the-kernel-owns-the-call) — the emit takes the caller's session and the **Checkpoint 6 Kernel** owns the call, implementing ADR-004 4.7 and avoiding the circular `storage` to `events` dependency section 2.2 forbids. **Not enforced by construction; a required check at Checkpoint 6.**
  - [6.10 Reaffirmed, Not Newly Decided](../adr/ADR-006.md#610-reaffirmed-not-newly-decided) — PostgreSQL is the durable store and LISTEN/NOTIFY only a wake-up (ADR-002); no version column, no update, and no delete on either append-only table; **no new runtime dependency and no message broker.**
  - **Amendment — Checkpoint 5 Implementation Ruling, 2026-09-04.** One Builder ruling made while implementing this checkpoint; §6.1 to §6.10 stand unchanged.
    - [6.11 The Event Vocabulary Belongs To The Domain Layer](../adr/ADR-006.md#611-the-event-vocabulary-belongs-to-the-domain-layer) — `EventType`, `TransitionOutcome`, `OSEvent`, and `TransitionAuditRecord` live in `domain/`; `events/` keeps the envelope, channel, emitter, and subscriber. Resolves a circular dependency the Blueprint section 11 layout requires, **the same way ADR-004 4.7 resolved it for the condition vocabulary**. A placement ruling only: no field, value, or invariant changes, and no `AggregateType` vocabulary is invented.


- [ADR-007: The Four Blocked Conditions & Checkpoint 6 Preconditions](../adr/ADR-007.md) — **Accepted — 2026-09-05.** Records the four Builder rulings that discharge `BLOCKED_CONDITIONS` and unblock Checkpoint 6. **Supersedes nothing**; fills the gaps left open by Blueprint section 14 items 15 to 18, ADR-004 4.11, ADR-005 *Questions Not Decided* 3, and ADR-006 *Questions Not Decided* 4. Two rulings tighten an existing invariant and both are recorded as tightenings.
  - [7.1 An Implementation Task Is Any Task Whose Capability Is Not QA](../adr/ADR-007.md#71-an-implementation-task-is-any-task-whose-capability-is-not-qa) — a **ruling, not an inference**: `ALL_IMPLEMENTATION_TASKS_ACCEPTED` covers non-QA Tasks only, while `ALL_TASKS_ACCEPTED` still covers every Task including QA. **No new field.** A per-Task non-blocking flag was rejected — a gate with a per-record off-switch is defeated by the first mislabelled record. Non-blocking work, if ever needed, is a **new `CapabilityType`**, not a flag.
  - [7.2 Code, Tests And Reasoning Are The Feature-Level Evidence Set](../adr/ADR-007.md#72-code-tests-and-reasoning-are-the-feature-level-evidence-set) — `GIT_DIFF`, `TEST_OUTPUT`, `REASONING`, at least one of each across the Feature's evidence closure. A Feature-level floor that **does not modify `MANDATORY_SYSTEM_EVIDENCE`**. `API_RESPONSE` and `DB_VERIFICATION` excluded because they are not true of every Feature. **Recorded limitation:** the OS checks that `REASONING` exists, never that it is good; the plain-English standard is enforced by the Builder, not by the system.
  - [7.3 Reviewers Are Routed By Capability And May Never Review Their Own Work](../adr/ADR-007.md#73-reviewers-are-routed-by-capability-and-may-never-review-their-own-work) — `Task.reviewer_id` added; eligibility is active + `REVIEWER` role + matching capability + **not the Worker and not the author of any Revision**, which makes **ADR-001 machine-enforced for the first time**. Deterministic selection ascending by `ActorId`; an empty eligible set **refuses the transition**. Tightens the `Actor` capability invariant to `REVIEWER`. **Load balancing, delegation, reassignment and escalation are deferred**; ascending id is deterministic, not fair.
  - [7.4 QA Rounds Select The Current Defect Position](../adr/ADR-007.md#74-qa-rounds-select-the-current-defect-position) — `Feature.qa_round` starting at 1, incremented **only** on the `IN_VALIDATION -> IN_PROGRESS` rework loop; `QAReport.qa_round` **stamped by the Kernel at recording time**, never by the reporting Actor and never from a clock. Acceptance rules consider the current round only. **Respects both pre-closed answers** — ADR-005 5.9 (no persistence timestamps) and ADR-006 6.1 (`sequence_number` selects nothing). Supersession pointers and per-defect resolution both rejected, the latter because it would unsettle QA Report immutability. **The round filter is performed by the rule, not the loader**, correcting `QAInScopeZeroDefectsRule`'s deferral now that a selector exists. **Not enforced by construction** — the single-increment invariant is a required Checkpoint 6 test, the same class of risk as ADR-006 6.9.
  - [7.5 `TASKS_INSTANTIATED` Is Discharged By Machinery, Not By Ruling](../adr/ADR-007.md#75-tasks_instantiated-is-discharged-by-machinery-not-by-ruling) — no Builder ruling owed; the Checkpoint 6 runner instantiates the Tasks and asserts the outcome it produced. Recorded so the gate arithmetic is explicit: **three of four blocked conditions answered by ruling, the fourth by building Checkpoint 6.**
  - **Implemented by Checkpoint 6, 2026-09-05.** All four rulings landed as registered rules; 7.5 landed as `OSKernel.activate_plan`. The Rule Coverage Gate passes: 21 of the 24 required conditions enforced by a rule, 2 by a domain invariant, 1 performed by the Transition Runner.
  - [7.6 Reaffirmed, Not Newly Decided](../adr/ADR-007.md#76-reaffirmed-not-newly-decided) — ADR-001, QA Report immutability, ADR-005 5.9, ADR-006 6.1, `MANDATORY_SYSTEM_EVIDENCE`, and the `CapabilityType` and `EvidenceType` vocabularies all stand unchanged. **No new runtime dependency and no new table.**

- [ADR-008: HTTP Control Plane Architecture & Checkpoint 7 Scope](../adr/ADR-008.md) — **Accepted — 2026-09-05.** Records the architecture of the HTTP control plane and the scope of Checkpoint 7. **Supersedes nothing**; rules on the Blueprint section 9.1 header recommendation rather than letting an implementation adopt it silently, and supplies the HTTP mapping ADR-005 5.12 deferred to this checkpoint. Two rulings are the Builder's and four the author's under the Builder's standing delegation; the record says which is which.
  - [8.1 Caller Identity Is Read From Headers](../adr/ADR-008.md#81-caller-identity-is-read-from-headers-and-resolved-against-actors) — **Builder ruling.** `X-Actor-ID` and `X-Actor-Role` resolved through one dependency, with the Actor looked up and **the declared role checked against the recorded role** — without that check Checkpoint 6's entire authority layer would be decorative. **Recorded limitation: this is identification, not authentication.** Anyone who can reach the API can impersonate any Actor. Adequate while the OS runs where the Builder controls it; not adequate on an open network, and not claimed to be. `X-Domain-ID` is accepted and unused because ADR-003 3.10 defers the Domain Registry.
  - [8.2 A Refusal Is 422, And Only A Refusal Is](../adr/ADR-008.md#82-a-refusal-is-422-and-only-a-refusal-is) — **Builder ruling.** 422 for every OS refusal, state machine and Rule Engine alike; 404 absent, 409 concurrent change, 400 malformed, 500 OS failure. **An unauthorised role is a 422, not a 403** — it is the state machine refusing, and splitting it out would put one idea in two places. Completes ADR-005 5.12. The structured reasons are the machine contract; the status is only a category.
  - [8.3 Named Action Endpoints](../adr/ADR-008.md#83-named-action-endpoints-not-a-generic-transition-endpoint) — `submit`, `assign`, `approve`, `accept`, `activate`, `return-for-rework`, not one generic transition endpoint per entity. Each endpoint demands exactly the data its action needs, so a malformed request is refused at the door instead of travelling to the Kernel to fail there. **The API is a contract with callers, not a mirror of internals.**
  - [8.4 One Transaction Per Request](../adr/ADR-008.md#84-one-transaction-per-request-opened-by-the-route-owned-by-the-kernel) — one `UnitOfWork`, one `OSKernel`, **one Kernel call**. Two Kernel calls would mean two commits and two outcomes for one request. An operation spanning two transitions belongs in the Kernel, as `activate_plan` already does.
  - [8.5 A Route Reads Identity, Calls One Kernel Method, And Translates](../adr/ADR-008.md#85-a-route-reads-identity-calls-one-kernel-method-and-translates) — exactly three steps and no fourth. **No route evaluates a rule, reads a repository, or writes anything.** A route needing more is evidence that logic landed in the wrong layer; pinned by a test that no route module imports `storage`, `rules`, `state` or `events`.
  - [8.6 Checkpoint 7 Exposes No Event Stream](../adr/ADR-008.md#86-checkpoint-7-exposes-no-event-stream) — **Builder ruling.** Endpoints for *doing*, none for *watching*. Reading the stream becomes its own work taken up **immediately after**, because how a live view reads a growing stream without hammering the database deserves its own design. **Cost accepted: the UI stays on scripted events one checkpoint longer.** ADR-006 6.5 stays deferred for a sharper reason — the consumer exists, the transport does not.
  - [8.7 Reaffirmed, Not Newly Decided](../adr/ADR-008.md#87-reaffirmed-not-newly-decided) — the Kernel stays the only writer; ADR-005 5.12, Blueprint section 9.1 provider independence and ADR-003 3.10 all stand; the typed client SDK remains Checkpoint 8. **No new runtime dependency.**
